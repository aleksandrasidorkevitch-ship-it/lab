## Постановка задачи
В файле сценариев две ветки уточняют основные шаги и граничные случаи. Необходимо сымитировать конфликт слияния, разрешить его и выложить на GitHub.

## Ход работы

### 1. Создание локального репозитория
Локальный репозиторий инициализирован командой git init. Создан начальный файл acceptance.feature с базовым сценарием. Выполнен первый коммит.

### 2. Работа в ветках
- Создана ветка happy-path: в файл acceptance.feature добавлены детали основного сценария (авторизация, подтверждение оплаты).
- Создана ветка edge-cases: в те же строки файла добавлены граничные случаи (товар заканчивается на складе).

### 3. Сценарий конфликта
При попытке слияния ветки edge-cases в main (после слияния happy-path) возник конфликт, так как обе ветки меняли одни и те же строки. 

Фрагмент конфликтных маркеров, который вывел Git в файле acceptance.feature:

<<<<<<< HEAD
    And пользователь авторизован
    When пользователь нажимает "Оформить заказ"
    And подтверждает оплату
    Then заказ успешно создан и отправлен на почту
=======
    And на складе осталась 1 штука
    When пользователь нажимает "Оформить заказ"
    Then заказ успешно создан, но товар закончился
>>>>>>> edge-cases

### 4. Разрешение конфликта
Маркеры <<<<<<<, =======, >>>>>>> были удалены вручную. Итоговый сценарий переписан так, чтобы учесть оба условия (авторизацию и ограниченный остаток на складе). 

После редактирования выполнены команды:
- git add acceptance.feature
- git commit -m "Разрешен конфликт: объединены happy-path и edge-cases"

### 5. Публикация
Проект добавлен в общий учебный репозиторий.
